SpotiDuck — interface mobile

bundle v… mock du web player Spotify ouvrir en plein écran ↗

Appareil

Scénarios

« Transfert » = Spotify joue sur un autre appareil : la couche doit cliquer « Écouter sur cet appareil » puis démarrer la lecture. « Connexion » = page de login mobile avec le bouton e-mail/mot de passe. « Hors ligne » = bandeau rouge au-dessus du mini-player.

À vérifier

  • Barre d'onglets : 3 onglets, l'actif est blanc et rempli.
  • Mini-player : apparaît dès qu'un titre joue, la ligne de progression avance, swipe ←/→ = piste suivante/précédente, swipe ↑ = plein écran.
  • Lecteur plein écran : chevron pour fermer, glisser vers le bas pour fermer, poser le doigt sur la barre de progression pour scrubber, « … » = menu (file d'attente, paroles, appareils, artiste, album, partager, paramètres).
  • Paramètres : engrenage dans l'en-tête de la bibliothèque ou menu « … » → thème Auto/Sombre/Clair, animations, prise de contrôle, rechargement du lecteur.
  • Retour matériel : ferme d'abord le panneau ouvert, puis le lecteur, puis quitte l'appli.
  • Bibliothèque : plein écran, titre collant, lignes de 64 px, sous-titre sans les « • • » cassés.
  • Recherche : champ unique en haut, cartes en 2 colonnes.
  • Connexion : formulaire lisible, champs de 48 px, bouton « e-mail + mot de passe ».
  • Aucun chevauchement avec la barre système, même en paysage.

Notes

Le mock reproduit la structure DOM du web player desktop (mêmes data-testid). La couche mobile ne modifie jamais le DOM de Spotify : elle lit les nœuds existants et dessine sa propre interface par-dessus.
